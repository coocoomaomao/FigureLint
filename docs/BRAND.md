# FigureLint Brand Guide

FigureLint's visual identity combines **academic-tool clarity** with a friendly **black cat mascot**.

## Core idea

The mascot is a cute black cat inspecting an academic figure with a magnifying glass and a check mark.

The visual language should communicate:

- careful inspection
- trustworthy technical tooling
- research / publication quality
- friendliness and approachability

## Primary tagline

**ESLint for academic figures.**

Supporting line:

**Catch publication-quality problems in academic figures before submission.**

## Mascot

Use a simple black cat with:

- rounded head and ears
- large expressive eyes
- small pink nose
- teal magnifying glass
- optional check mark
- minimal line-art details

The mascot should feel cute, but the overall composition should still look professional enough for a research/software project.

## Color palette

| Role | Hex | Usage |
| --- | --- | --- |
| Primary navy | `#1F3A5F` | wordmark, outlines, headings |
| Teal | `#2CB1A1` | magnifying glass, checks, highlights |
| Warm orange | `#F4A261` | small accent details only |
| Soft background | `#F6F8FB` | banners, cards, documentation backgrounds |
| Cat black | `#111820` | mascot body |

## Logo system

Planned official assets:

- **Primary logo** — cat + figure + magnifying glass + FigureLint wordmark
- **Horizontal logo** — compact mascot + FigureLint
- **Icon / favicon** — cat head or cat head inside magnifying glass
- **Dark-background logo** — light-outline variant
- **README banner** — mascot + wordmark + one-line value proposition

## Tone

FigureLint should feel:

- clear
- useful
- trustworthy
- lightweight
- friendly

Avoid:

- overly corporate visual language
- overly childish cartoon styling
- excessive gradients
- cluttered scientific imagery

## Suggested copy

Short:

> ESLint for academic figures.

Medium:

> FigureLint checks academic figures for common technical quality issues before submission.

Long:

> FigureLint is an open-source linter for academic figures. It helps researchers and students catch reproducible technical issues — such as DPI, dimensions, transparency, and export-format risks — before submission.

## Repository visual direction

The README should use plenty of whitespace and keep the first screen focused on:

1. logo / mascot
2. one-line description
3. CI / Python / MIT / alpha badges
4. quick-start example
5. current checks
